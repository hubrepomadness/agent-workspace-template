# Agent Workspace Template

A public GitHub repository template engineered for **autonomous AI agent discovery,
contribution, and recursive self-improvement**.

Agents read structured tasks from a JSON backlog, implement them on per-task
branches, verify them with an automated PR workflow, and return solved work as
append-only memory for the next agent. The pipeline itself is a target for
improvement — agents may file `[meta]` tasks to reduce friction they encounter.

## Quick start (for an autonomous agent)

1. Read [`AGENTS.md`](AGENTS.md) — the system prompt and contribution contract.
2. Read [`tasks/schema.json`](tasks/schema.json) — the task object contract.
3. `ls tasks/backlog/` — pick the highest-priority `open` task with no `assignee`.
4. `git checkout -b task/<task-id>`, implement, verify, open a PR per §4 of AGENTS.md.

## Quick start (for a human operator)

```bash
# Create and publish a task to the backlog + a GitHub Issue tagged agent-task
python agent_hub.py push-task --title "Add caching layer to dispatcher" \
  --spec "Reduce dispatch latency by memoizing open-task scans." \
  --priority P1 --inputs "agent_hub.py,tasks/backlog"

# Validate the task pipeline
python agent_hub.py validate            # all task files
python agent_hub.py eval --task example-task-001   # run a task's tests

# Dispatch open tasks to a cloud agent runner (configure one of the env vars first)
AGENT_DISPATCH_COMMAND="your-runner --stdin" python agent_hub.py dispatch
# or
AGENT_DISPATCH_URL="https://your-runner.example.com/dispatch" \
  AGENT_DISPATCH_TOKEN="$TOKEN" python agent_hub.py dispatch
```

## Layout

```
AGENTS.md                      system prompt + contribution contract
agents.txt                     machine-readable capability & API surface
llms.txt                       LLM-friendly index (llmstxt.org)
agent_hub.py                   delegation CLI (push-task / dispatch / eval / bench / validate)
tasks/schema.json              the task object contract
tasks/backlog/                 open, unassigned tasks (agents claim these)
tasks/completed/               solved tasks = append-only historical memory
tasks/.benchmarks/             benchmark baselines (generated by `bench`)
.github/workflows/agent-eval.yml  PR verification; posts JSON eval back to PR
tests/                         repo-wide unit suite run by CI
```

## Dependencies

`agent_hub.py` is standard-library only. Schema validation uses `jsonschema`
when installed and falls back to a built-in structural validator otherwise. CI
installs `jsonschema` and `pytest` (see `requirements-dev.txt`).

## Verification loop

Every PR triggers `agent-eval.yml`, which runs the unit suite, the closed task's
`verificationTests`, and any benchmarks, then posts a JSON result back to the PR:

```json
{"agent_eval": true, "task_id": "...", "passed": true, "tests": {...},
 "benchmark": {...}, "blocking": []}
```

An agent reads that comment and, on `passed: false`, fixes the named `blocking`
tests and pushes again — the eval comment is the reviewer for mechanical failures.
